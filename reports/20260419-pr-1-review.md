# PR #1 Review — `fix: improve QR code authentication with HTML file generation`

## 背景

PR 试图修复终端 ASCII 二维码被截断、无法扫描的 UX 问题。验证当前 main：`scripts/auth.py` 的 `render_qr` 从 7e77a63 初始提交至今未被改动，确实没有任何针对 QR 截断的降级路径。问题真实存在，方向正确。

但实现引入 5 个 Critical / 5 个 Important 问题，需返工。

## 🔴 Critical — 合并前必须修

### C1. Security (High) — Symlink/TOCTOU via 硬编码 /tmp 路径

**Location**: new `scripts/auth.py` L80-81 (diff)
**Threat**: 在多用户 Linux 主机上，攻击者可预先 `ln -s ~victim/.ssh/authorized_keys /tmp/jike_qr_login.html`。`open(html_path, 'w')` 跟随软链接，覆盖目标文件（CWE-59/CWE-377）。
**Fix**: `tempfile.NamedTemporaryFile(mode='w', suffix='.html', delete=False)` 产生不可预测路径，或 `os.open(path, O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o600)`。

### C2. Error handling — try 只 catch ImportError，I/O 异常全部逃逸

**Location**: new `render_qr` try 块
**Symptom**: `PermissionError`、`FileNotFoundError`（Windows 无 `/tmp`）、`OSError ENOSPC`（tmpfs 满）、`qrcode.make_image()` 依赖的 PIL 异常 —— 全部未捕获，直接崩溃整个 auth 流程（连 fallback 都走不到）。
**Fix**: 拆成两个 try：`ImportError` 一个，`(OSError, IOError)` 一个；后者 log 后 `return False` 让 caller 走 raw URL 降级。

### C3. Error handling — `return True` 语义失效

**Location**: `scripts/auth.py:111` 调用处
**Symptom**: HTML 写成功但 ASCII `print_ascii` 抛异常（Windows cp936 编码错误 / broken pipe）时会整体 crash。反过来 ASCII 先打印成功、HTML 写失败时 caller fallback 打印 raw URL 又会出现在 ASCII QR 下面，用户不知道该扫哪个。
**Fix**: 独立跟踪 `html_ok` / `ascii_ok`，`return html_ok or ascii_ok`。

### C4. Docs — "自动生成 HTML" 误导

**Location**: `SKILL.md:28`
**Claim**: "A QR code HTML page is automatically generated at /tmp/jike_qr_login.html"
**Reality**: HTML 生成整段在 `try: import qrcode` 里。没装 qrcode 的用户 fallback 到打印 raw URL，`/tmp` 根本没文件。
**Fix**: "When the `qrcode` library is installed, a QR code HTML page is generated at..."

### C5. Docs — HTML / ASCII 依赖关系反转

**Location**: `SKILL.md:29`
**Claim**: "**Terminal ASCII** — If qrcode library is installed, an ASCII QR is **also** printed"
**Reality**: HTML 和 ASCII 共用一个 `import qrcode` gate。它们要么同时出现，要么同时缺失；"also" 暗示的"HTML 是基线、ASCII 是附加项"是错的。
**Fix**: 合并两点："If `qrcode` is installed, both an HTML file and an ASCII QR are produced. Otherwise, the raw `jike://` URL is printed for manual scan."

## 🟡 Important — 应当修

### I1. Security (Medium) — 世界可读文件 + 无清理 = session 劫持窗口

**Location**: `scripts/auth.py` L80-81
**Threat**: 默认 umask 0644，`/tmp/jike_qr_login.html` 世界可读。`poll_confirmation` 180 秒窗口里，同机任意用户可 `cat` 读走 HTML → 解码 base64 PNG → 用自己的即刻 App 扫码抢先确认 session。auth 结束后文件还**不清理**，持续泄漏。
**Fix**:
1. 创建文件立即 `os.chmod(path, 0o600)` 或用 `os.open(..., 0o600)`
2. `poll_confirmation` 包 `try/finally`，finally 里 `os.unlink(path)`

### I2. Code quality — `render_qr` 违反单一职责

**Location**: new `render_qr` L49-92 (diff)
**Evidence**: 一个函数做 6 件事：构 QR 矩阵 / PNG→base64 / 装 HTML 模板 / 写磁盘 / 两行 stderr / 渲染 ASCII。40 行的 god function，之前是 6 行。
**Fix**: 拆分 `_build_qr` / `_qr_to_png_base64` / `_write_qr_html` / `render_qr`(orchestrator)。

### I3. Code quality — 重复构造 QR 矩阵

**Location**: new L49-51 + L88-90
**Evidence**: 为 HTML 建一个 `QRCode(box_size=10)`，为 ASCII 又建一个 `QRCode(box_size=2)`。`box_size` 只影响像素渲染，对 `print_ascii` 无意义。
**Fix**: 一个 `QRCode` 实例就够，`make_image()` 和 `print_ascii()` 都在它上面调。

### I4. Cross-platform — 硬编码 `/tmp` 在 Windows 上直接挂

**Location**: new L79
**Evidence**: `html_path = '/tmp/jike_qr_login.html'`
**Fix**: `Path(tempfile.gettempdir()) / 'jike_qr_login.html'`，URL 用 `html_path.as_uri()`。

### I5. Code quality — `uuid` 参数是 leaky abstraction

**Location**: signature `render_qr(data, uuid)` 
**Evidence**: 新加的 `uuid` 纯粹为了在 HTML 页脚显示 "Session: {uuid}"；而 `uuid` 本就嵌在 `data` 里（`build_qr_payload` 生成），caller 也在 L108 已经打印过一次。
**Fix**: 删掉 `uuid` 参数。想要 HTML 页脚显示提示，传 `caption: str = ""` 更通用。

## 🔵 Suggestions

- **S1** Security (Low) — `{uuid}` f-string 插入 HTML 无 escape。若 API 返回畸形 UUID（MITM 场景）可在 `file://` origin 触发 XSS。修：`html.escape(uuid)`
- **S2** Magic numbers — `version=1, box_size=10, border=2` 应提为模块常量
- **S3** Import 位置 — `base64` / `BytesIO` 是 stdlib，应放顶层 import；巨大 HTML 字符串应提为模块常量或独立模板文件
- **S4** Return value — `bool` 信息量不足，考虑 `RenderResult(html_path: Optional[Path], ascii_printed: bool)`
- **S5** Caller fallback message — `"Install 'qrcode' for terminal QR"` 在 render_qr 失败原因扩展后变误导
- **S6** SKILL.md 文案 — 没提 /tmp 文件持久化行为、清理时机、Windows 不支持；docstring `"""Render QR both as ASCII and HTML file for better UX."""` 没描述磁盘副作用

## ✅ Strengths

1. 解决真实 UX 问题，终端 ASCII QR 在多数终端确实截断
2. 保留向后兼容，ASCII 路径未删
3. HTML 用 base64 内嵌 PNG，离线自包含，不引入新外部资源或依赖
